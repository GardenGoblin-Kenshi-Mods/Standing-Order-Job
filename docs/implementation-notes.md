# Standing Order Job — implementation notes

Mod-specific design decisions and internal invariants for `Standing Order Job`. Authoritative behavioral scenarios live in [`docs/behaviors.md`](behaviors.md); shared Meitou `apiVersion: 2` conventions live in the Factory `docs/code-mod-patterns.md`.

## Classification & IDs

- **Classification:** Pure Meitou `apiVersion: 3` C# code mod (empty `.mod` header generated by `tools/Program.cs`).
- **TaskType claimed:** `400000` (Garden Goblin reserved block `400000+`, well above `SimulationExtensions.FirstModCode` `1000`), display name `"Stand Here"`.
- **Debug env:** `MEITOU_STANDING_ORDER_JOB_DEBUG=1`.

## Design decisions & invariants

1. **Menu-row gating & mixed selections:** `StandHereUi.Verbs` explicitly checks `context.Target.IsPlayer && !context.Target.Animal && context.Selected.Contains(context.Target.Id)` before emitting `"Stand Here"`. On mixed selections, `StandHereSystem.Apply` additionally filters out animals, non-players, and dead characters (`Medical is { Dead: false }`), validating finite coordinates (`StandHereTypes.IsFinitePoint(point)`).
2. **Incapacitated assignment vs execution:** `Apply` allows Shift-assigning/updating a `Stand Here` job on living incapacitated squad mates; `StandHereJobs.CanRun` gates execution on `Incapacitated == false` so they wait until conscious and then walk to the point.
3. **Unshifted delegation:** Without Shift, `Apply` calls `world.Defer(new MoveOrder(recipients, command.Point) { Tick = world.Tick + 1 })`, leaving `_points` and existing jobs untouched.
4. **In-place job updates & priority blocking:** `AssignJob` updates existing `PermaJobs.IndexOf(cold, 400000)` entries in place rather than appending, preserving Jobs panel order because an always-eligible `Stand Here` blocks lower jobs beneath it.
5. **Arrival hold (`NearRadius = 1.5f` horizontal):** Arrival transitions the hot task from `GoTo` to `Idle` while `cold.Running.Task` may remain `GoTo`; `CanRun` checks `IsNearPoint(currentPosition, standPoint)` (2D XZ distance `<= 1.5f`) before `runningTask.Runs(currentTask)` to avoid repath spam, and `Start` guards `GoTo` with `DestinationAccess.WalkRefused`.
6. **Configurable return distance & `SettingsBridge`:** `StandHereSettings` registers `Max return distance (m)` (`0..2000`, `DefaultDistanceMeters = 652` matching `ProductionSystem.JobRangeSq` ~651.7 m, `0 = unlimited`) **before** `SettingsBridge` initializes so persisted `meitou.user.json` values take effect on startup. `SettingsBridge` uses `System.Threading.Lock`, drains dirty updates at the start of serial `Inputs`, and triggers `RequestReplanForAssigned` (`DecisionSystem.Request` sorted by `LastingId.Value`) whenever the cap changes. `StandHereTypes.IsWithinReturnRange` converts metres via `WorldUnitsPerMeter = 10f` and checks strict 3D `Vector3.DistanceSquared < maxDistanceSquared`; `StandHereJobs.CanRun` returns `DecisionCheck.No("out of range")` beyond the cap (preserving `CharacterOrders.Jobs`, the job row, and `_points[lasting]`), and `Start` repeats the guard.
7. **Unloaded zones, removal & persistence (`SaveFormat = 1`):** `PruneAndCancel` preserves `_points[lasting]` when `world.LastingIds.Find(lasting).IsNone` (unloaded zones), drops entries when the resolved character slot is gone or `PermaJobs.IndexOf < 0`, and runs `CancelGhostWalk` on job removal. `IStateHashed` hashes `_maxReturnDistanceMeters` followed by sorted `_points` entries; `IModSaveData` remains at `SaveFormat = 1` because Mods-page settings are saved in `meitou.user.json`.
8. **v0.1 scope boundary:** Each recipient gets the clicked target's exact snapshot position; formation spread is intentionally omitted.

## Build provenance & reproducibility

- **Deterministic Release + embedded PDB:** `src/StandingOrderJob.csproj` builds `Release` (`Optimize=true`) with `Deterministic=true`, `ContinuousIntegrationBuild=true`, `DebugType=embedded`, `EmbedAllSources=true`, and .NET 11 SDK Source Link (`PublishRepositoryUrl=true`, `RepositoryUrl=https://github.com/GardenGoblin-Kenshi-Mods/Standing-Order-Job`, plus offline `SourceRoot` fallback when `EnableSourceControlManagerQueries=false`).
- **Offline Nix build:** `flake.nix` + `flake.lock` + `nix/deps.json` pin `nixpkgs`, `dotnetCorePackages.sdk_11_0`, `MeitouClient`, and every NuGet package so CI and local Linux/WSL2 builds run offline inside Nix's sandbox (`sandbox = true`).
- **Non-circular manifests & attestations:** `tools/archive-package.sh` builds a deterministic ZIP (fixed `1980-01-01` timestamps, sorted POSIX paths, normalized permissions) and emits `.contents.sha256` and `.zip.sha256`. Release CI scans `StandingOrderJob.binlog` via `tools/check-binlog-secrets.sh` and attests both `StandingOrderJob.dll` and `StandingOrderJob-<version>.zip` with `actions/attest-build-provenance@v2` without modifying either file afterward.
